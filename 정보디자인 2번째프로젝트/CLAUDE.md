# 검정치마 3집 앨범 인터페이스

정보디자인 프로젝트 2 (그레고리 강사). 작업자: 햄.
이 문서는 Claude(Cowork)에서 진행한 기획, 데이터, 결정을 Claude Code로 넘기기 위한 인계 문서다.

---

## 0. Claude Code가 지킬 것 (가장 먼저)

1. **햄의 설계를 따른다.** 기획과 경험 설계는 햄이 정한다. 제안은 하되 임의로 바꾸지 않는다.
2. **화면에 올라가는 모든 요소는 이유가 있어야 한다.** 의도 없이 놓인 텍스트, 숫자, 라벨, 번호, 장식은 넣지 않는다. 요소를 넣을 때마다 "이게 지금 여기 왜 있어야 하나"를 한 줄로 말할 수 있어야 한다.
3. **설명하는 문장을 쓰지 않는다.** "꽃 한 송이가 곡 하나다" 같은 안내 문구 대신 화면과 인터랙션이 설명해야 한다.
4. **정보는 순서대로, 필요한 순간에 나온다.** 한꺼번에 쏟지 않는다.
5. **가사 원문을 화면이나 파일에 싣지 않는다.** 데이터는 태그, 글자 수, 단어(상징어)만.
6. **문구에 중간점(·)과 AI 말투를 쓰지 않는다.** (교수님 지적)
7. **작업 방식은 모듈 단위 + 조정 패널(슬라이더)** 로 나눠 만들고, 햄이 손으로 맞춘 값을 다시 받아 반영한다. (교수님 방식)

## 1. 질문과 메시지

- **질문:** 같은 사랑을 어떻게 다르게 표현했나
- **범위:** 검정치마 정규 3집 세 파트만. TEAM BABY (2017, 10곡), THIRSTY (2019, 12곡), TEEN TROUBLES (2022, 18곡). 1집, 2집은 버렸다.
- **메시지 초안:** 같은 사랑을 TEAM BABY는 약속으로, THIRSTY는 몸으로, TEEN TROUBLES는 기억으로 썼다.
- **왜 3집인가:** 세 파트는 거의 같은 시기에 만들어졌다 (TEAM BABY와 THIRSTY는 동시 작업, 본인 인터뷰). 같은 사람이 같은 시기에 쓴 사랑이 세 갈래로 나뉜 것이라 비교가 성립한다.

### 데이터가 보여주는 차이 (근거)

| | TEAM BABY | THIRSTY | TEEN TROUBLES |
|---|---|---|---|
| 태도 평균 (1 어두움 ~ 5 밝음) | 3.9 | 1.9 | 2.9 |
| 곡 끝맺음 | 10곡 중 6곡이 가장 밝게(5) | 12곡 전부 어둡게(1~2) | 섞임 |
| 약속, 부탁 (미래형) | 16% | 12% | 13% |
| 몸을 말하는 문장 | 7% | 13% | 7% |
| 회상 (과거형) | 7% | 13% | 14% |
| 직유 ("~처럼") | 9.7% | 2.0% | 5.4% |
| 실명, 장소 | 5.2% | 2.8% | 14.1% |

- 약속, 몸, 회상 비율은 **어미와 단어 정규식으로 자동 분류한 시험값**이다. 차이가 작다. 정식 태깅이 필요하다 (아래 6번).
- 가장 확실한 차이는 **태도(밝기)와 끝맺음**이다.
- 곡끼리 이어지는 말: TEAM BABY 「Love Is All」의 첫 네 줄이 THIRSTY 「피와 갈증」에 가사와 멜로디째 인용된다 (태도 4.2 → 1.7). 「난 아니에요」(TEAM BABY 첫 곡)와 「피와 갈증」(THIRSTY 마지막 곡)이 같은 호칭으로 이어진다. 「폭죽과 풍선들」 → 「Bollywood」.

## 2. 경험 설계 (햄이 정한 것)

**큰 메타포: 앨범.** 웹사이트가 아니라 앨범을 여는 인터페이스. 요즘 앨범처럼 박스 안에 **부클릿, LP, 플레이어**가 함께 들어 있다. 3집은 세 파트이므로 **LP 세 장짜리 박스 세트**.

**읽는 순서: 제목 → 인코딩 방식과 예시 → 데이터 시각화**

| 순서 | 물건 | 역할 (왜 있나) |
|---|---|---|
| 1 | 커버 | 제목 (질문 하나). 열면 부클릿이 나온다 |
| 2 | 부클릿 | 읽는 법. 문장 하나가 홈 조각 하나가 되는 과정을 보여준다. 표로 설명하지 않고 바뀌는 과정으로 알게 한다. 뒷장에는 곡별 개별 데이터 |
| 3 | LP 세 장 | 부클릿의 규칙으로 앨범 하나를 통째로 새긴 무늬. 세 장을 나란히 두면 설명 없이 다르다는 게 보인다. 메시지가 여기서 전달된다 |
| 4 | 플레이어 | LP를 넣고 바늘을 내리면 재생. 시간이 있어야 보이는 것(곡의 흐름, 끝맺음)을 보여준다 |

- 나중에 추가할 깊은 층: 비유와 상징 (data/상징_비유_해석표.csv). 메시지는 바뀌지 않는다.
- 꽃 메타포는 LP로 바꾸면서 빠진다 (메타포가 둘이면 흐려짐). 이전 꽃 프로토타입은 reference 폴더에 참고용으로만.

## 3. 인코딩 (초안, LP 홈)

| 홈의 속성 | 데이터 | 값 |
|---|---|---|
| 홈 한 조각 | 문장 하나 | |
| 홈 길이 | 문장 길이 | `n` (글자 수) |
| 색상 | 주제 | 태그 1번째 글자 |
| 밝기 | 태도 | 태그 2번째 글자 (1~5) |
| 선명함 (채도) | 감정의 세기 | 태그 3번째 글자 (1~3) |
| 홈의 결 | 말하는 방식 | `m` (약속은 매끈, 몸은 거칠게, 기억은 흐리게) |
| 빈 홈 | 곡과 곡 사이 | |
| 트랙 순서 | 1번 트랙이 가장 바깥 | `tr` |

### 색 규칙 (확정)
- **색상 = 주제:** L 사랑 h22 (빨강) / F 사람들 h150 (초록) / S 나 자신 h255 (파랑) / H 가족, 고향 h55 (주황) / W 세상, 일상 h305 (보라). 노랑은 쓰지 않는다.
- **명도 = 태도:** 밝을수록 긍정, 낙천. 어두울수록 이별, 회의, 권태. 이별은 따로 주제가 아니라 사랑을 대하는 어두운 태도다.
- **채도 = 세기:** 선명할수록 강렬하고 건강한 감정, 탁할수록 약함.
- 원칙: 색상, 명도, 채도는 각각 하나의 기준만 맡는다. 섞지 않는다.
- OKLCH로 계산. 명도는 가운데 구간(0.34~0.76 정도)만 쓴다. 참고 함수:

```js
const HUE={L:22,F:150,S:255,H:55,W:305}, CH={L:.20,F:.15,S:.16,H:.14,W:.15};
function col(tag,a=1){ // tag 예: 'L43'
  const att=(+tag[1]-1)/4, it=(+tag[2]-1)/2;
  return oklch(.34+.42*att, .02+(CH[tag[0]]-.02)*(.35+.65*it), HUE[tag[0]], a);
}
```

## 4. 데이터 파일

### data/3집_문장태그.json (메인)
40곡 배열. 곡 하나:
```json
{"t":"난 아니에요","a":"TEAM BABY","tr":1,
 "n":[18,13,19, ...],          // 문장마다 글자 수
 "tag":["S31","S41","F31", ...], // 문장마다 주제+태도+세기
 "m":["그외","약속","그외", ...]} // 문장마다 말하는 방식: 약속, 몸, 기억, 그외, '-'(추임새)
```
- 태그 형식: `주제 태도 세기`. 주제 L 사랑, F 사람들, S 나 자신, H 가족 고향, W 세상 일상. 태도 1~5. 세기 1~3.
- 문장 단위: 종결어미나 문장부호에서 끊고 최대 두 줄. 후렴 반복은 처음 태그를 따름.
- `m`이 `'-'`인 문장은 추임새(oh, yeah 등). 홈을 그리지 않거나 빈 홈으로.
- Stand Still은 1집이라 없음.

### data/정규1-3집_문장태그_64곡.json
같은 형식(`m` 없음), 1~3집 전체. 지금은 안 씀. 비교가 필요할 때만.

### data/상징_비유_해석표.csv
상징어 66개. 열: 앨범, 곡, 상징어, 장치(은유, 직유, 말장난, 인용 등), 뜻(블로그 해석 요약), 출처. 나중에 깊은 층에서 사용.

### data/이미지어_목록.csv
가사 속 이미지 단어 488건. 열: 앨범, 곡, 문장 번호, 종류(이미지어, 직유), 단어, 범주(물, 몸, 방 집, 어둠 그늘 등), 주제, 태도, 세기. 직유 단어는 자동 추출이라 잡음이 섞여 있음.

### 해석 기준
가사는 해석의 여지가 있어서 데이터로 옮기려면 주관이 필요하다. **블로그 「진희의 서재」(네이버 fold1234)의 검정치마 가사 분석**을 해석 기준으로 빌렸다. 태그는 먼저 매긴 뒤 블로그와 대조해 어긋난 곳만 고쳤다. 결과물에 이 기준을 밝힌다.

## 6. 아직 정할 것 (햄이 결정)
1. **홈 배치:** 실제 LP처럼 나선 하나로 이어지게 vs 곡마다 한 바퀴씩 나이테처럼.
2. **재생의 소리:** 음원은 저작권 때문에 넣을 수 없다. 바늘과 홈 움직임만 / 데이터로 만든 소리(밝기에 따라 음이 바뀌는 정도).
3. **부클릿에서 몇 곡을 보여줄지:** 읽는 법 예시 곡은 **Love Is All로 확정** (booklet-pages.js 기본값). 예시 문장 번호와 곡별 페이지 범위는 미정.
4. **말하는 방식 정식 태깅:** 3집 약 830문장에 약속, 몸, 기억, 묘사 등을 사람이 읽고 매긴다 (지금 값은 정규식 시험값). 가사 원문은 햄의 원본 시트에 있다.
